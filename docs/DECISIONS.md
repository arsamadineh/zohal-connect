# DECISIONS.md - Architectural & Design Decisions

This document records deliberate design and technical decisions made for Zohal Connect, adhering to Rule R4 and R6.

## 001: Pinned Aether Upstream Release
- **Date**: 2026-10-10
- **Context**: Spec requires resolving the latest Aether release as of implementation start.
- **Decision**: Pinned upstream release `v2.3.0` (commit `6175b67df370ab856bcee07fe85b524031903956`, released 2026-10-04). SHA256 hashes recorded in `third_party/aether.lock`.
- **Status**: Accepted.

## 002: Aether Binary Distribution Strategy (T0.12)
- **Date**: 2026-10-10
- **Context**: T0.12 requires deciding whether to download official binaries or build from source.
- **Decision**: In accordance with Section 3.2 T0.12 default:
  - Linux (x86_64 and arm64): Official release binaries verified by SHA256.
  - Windows: If patch for `IP_UNICAST_IF` / `IPV6_UNICAST_IF` is feasible (T0.10), build patched Aether binary in CI; otherwise use official release binary with Plan B edge bypass routes.
  - Android: Use release binary / source build via cargo-ndk.
- **Status**: Accepted.

## 003: Proptest and Ureq Crate Authorization
- **Date**: 2026-10-10
- **Context**: Sections 7.9 and 10 explicitly require property testing (10,000 toggles) and fuzz testing with proptest or cargo-fuzz. Section 7.6 requires a tiny dedicated health probe client (ureq or rustls).
- **Decision**: Authorize `proptest = "1.6"` strictly as a dev-dependency for property and fuzz tests, and `ureq = "2.12"` for the verification probe client.
- **Status**: Accepted.

## 004: Real Aether Flag Corrections (Verified Against --help)
- **Date**: 2026-10-10
- **Context**: `docs/AETHER_NOTES.md` records the real v2.3.0 `--help`: scan modes are `turbo|balanced|thorough|verified|ironclad` (no `stealth`), and MASQUE H3 is selected with `--h3`/`--quic`.
- **Decision**: Renamed `ScanProfile::Stealth` to `Verified` in `zohal-proto` and Dart settings; pass explicit `--h3` for Masque3 rungs. No new dependency.
- **Status**: Accepted.

## 005: Android Connection Architecture (Tap-Does-Nothing Fix)
- **Date**: 2026-10-10
- **Context**: The Dart bridge only spoke to a Unix socket, which does not exist on Android, so `setDesired` was silently dropped and the connect control never reacted.
- **Decision**: Android control path is `MainActivity` MethodChannel/EventChannel (`app.zohal.connect/vpn`, `app.zohal.connect/vpn_state`) to a rewritten `ZohalVpnService` in `:vpn` that runs the real ladder (h3/h2/wg/gool with per-rung deadlines), spawns the staged `libaether.so` from `nativeLibraryDir`, verifies `warp=on` through SOCKS, establishes the TUN, and forwards packets via a new `zohal-android` Rust cdylib (`libzohal_tun.so`, tun2proxy `tun_fd` mode, no new crates). Dart shows optimistic state within one frame and converges to engine state (2 s rule). Aether binaries are fetched in CI and staged into `jniLibs/<abi>/libaether.so`; staged files are gitignored. cargo-ndk + NDK r28 build the JNI lib in CI with 16 KB page-size link flags.
- **Status**: Accepted.

## 006: Linux AppImage With Unprivileged Fallback
- **Date**: 2026-10-10
- **Context**: AppImage runs as a regular user, so TUN/policy-routing is unavailable without the system service, yet the release must "fully work".
- **Decision**: `tools/build-appimage.sh` assembles the Flutter bundle plus `zohald` and `aether` into one AppImage (built in release CI). The Dart bridge tries the system socket, then the user socket, then auto-spawns the bundled `zohald user`. The engine detects non-root (`libc::geteuid`, already a dependency) and applies the per-user GNOME/KDE system-proxy scope instead of TUN, journaling the restore. Icon generated by `tools/gen-icon.py` (stdlib-only PNG writer, sharp brand mark) and also shipped in the .deb.
- **Status**: Accepted.

## 007: Restore End-to-End Connection Verification After v0.1.3
- **Date**: 2026-10-10
- **Context**: Versions after v0.1.3 replaced the WARP trace verification with a raw TCP check on desktop and accepted failed Android HTTP probes as `connected/direct`. The desktop SOCKS probe also assumed every SOCKS5 success reply had a ten-byte IPv4 address field.
- **Decision**: Require the Cloudflare trace through the candidate SOCKS proxy to report `warp=on` or `warp=plus` before declaring connected on desktop or Android. Parse variable-length SOCKS5 reply addresses, clear all stale Aether last-connection files after failed candidates, and retain the v0.1.3 IPv4/API-fragment startup fallback.
- **Status**: Accepted.

## 008: Android Upgradeable Package Versioning
- **Date**: 2026-10-10
- **Context**: The v0.1.7 APKs still declared `versionCode = 1` and `versionName = "1.0.0"` in Gradle. Android package installation and upgrades can reject an APK whose version code is not newer than the installed package.
- **Decision**: Set the v0.1.8 Android package to `versionCode = 8` and `versionName = "0.1.8"`, aligned with Flutter `0.1.8+8`. Future releases must increment both values.
- **Status**: Accepted.

## 009: Strict Aether Scan Policy
- **Date**: 2026-10-10
- **Context**: Aether logs showed fallback rungs using `balanced` and `thorough`, while cached reconnects used a shortcut that did not make the endpoint-verification policy explicit. This caused slow, inconsistent behavior and allowed parameters outside the required policy.
- **Decision**: Zohal may start Aether only with `--scan turbo` for fresh discovery or `--scan verified` for cached/measured endpoints. The desktop backend enforces this at command construction regardless of stale settings or ladder data; Android uses the same ladder policy. The `--quick-reconnect` bypass is removed so cached candidates go through Aether's verified-endpoint scanner. All candidates still require SOCKS proxy-path and `warp=on|plus` verification before routing is changed.
- **Status**: Accepted.
